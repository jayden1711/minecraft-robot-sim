# minecraft-robot-sim

Train robots in Minecraft. Build a world, mark the task with blocks, type `/robot train`, watch robots learn live in-game, export a policy
that runs in plain MuJoCo (or later on a real robot).

**This is a simulation.** Minecraft is the world editor and the display. All physics is MuJoCo; Minecraft's physics is never used.
No result is claimed for real robots until milestone M4 measures it.

Status: milestone M0 (mod + server handshake, block-region to MuJoCo export). See [PLAN.md](PLAN.md) for the design,
[CRITIQUES.md](CRITIQUES.md) for the objections and the tests that answer them, [HANDOFF.md](HANDOFF.md) for the current state and next steps.

## How it fits together

```
vanilla Minecraft client --> headless Fabric server (mcrobot mod) --TCP loopback--> Python server (mcrobot) --> MuJoCo / mjlab
```

- `mod/`: server-side Fabric mod, one codebase for several Minecraft versions via Stonecutter (Java 17/21/25 by version). Reads blocks, sends them over a framed socket, will show ghost robots as display entities. No client mod is needed.
- `server/`: Python package `mcrobot`: protocol, block-region to merged boxes to MJCF, task markers, socket server. Tests in `server/tests/`.
- `scripts/`: test matrix and smoke tests, server setup/launcher (pinned downloads in `pins.tsv`), synthetic export, MuJoCo render (CPU), rollout check, demo data pack generator.
- `datapack/mcrobot_demo/`: data pack (generated by `scripts/gen_demo_datapack.py` and `scripts/gen_arena_datapack.py`): the demo mazes, the sky arena, its run timer and camera spots.
- `server-mc/`, `server-mc-test/`, `results/`, `.venv/`: git-ignored. Minecraft's own files never enter git.

Task blocks: gold block = goal, lava or red wool = hazard, pressure plate or banner = checkpoint, command block or beacon = spawn. Ice blocks (packed ice, ice, blue ice) export low sliding friction.
Commands (op only): `/robot ping`, `/robot export <from> <to>`, `/robot demo [arena|arena_v2]`, `/robot style <models|blocks>`, `/robot cam <1-8>`, `/robot stop`,
`/robot spawn <g1|go2|rover>`, `/robot train`, `/robot play` (the commands after `ping` and `export` are forwarded to the Python trainer; `cam` runs a data pack function).

## World scale

One setting: `meters_per_block` (physics metres per Minecraft block), default **0.5**, so the 1.32 m Unitree G1 is 2.6 blocks tall. Set it in the server's `config/mcrobot.properties`
(`meters_per_block=0.5`) or with the environment variable `MCROBOT_METERS_PER_BLOCK`. The mod writes it into the header of every export; the exporter, the collider merge, the markers, the
navigation grid and the ghost transforms all read it from there (nothing hard-codes a scale). Headers without the key are read as 1 m per block. Consequence: a block is half as big as the robot's
step limit allows for, so design for it (carpets are walkable steps, full blocks are not; corridors for a G1 are at least 2 blocks wide, ceilings at least 3 blocks).

## Robot look: resource pack and ghost styles

Ghost robots are server-side display entities; no client mod. Two styles, chosen with `/robot style`: `blocks` (one `block_display` per link, plain concrete colours; also the style for training swarms)
and `models` (one `item_display` per link whose `item_model` is a model of the server resource pack, built from the Menagerie G1 meshes by `scripts/build_pack.py`: cuboid approximations, plain
colours, no logos). The pack is generated (not committed), served over HTTP by `scripts/serve_pack.py`, and offered to players through `server.properties` (`resource-pack`, `resource-pack-sha1`,
`resource-pack-id`; `require-resource-pack=false`). One pack covers 26.3 and 1.21.11. Without the pack the models show as "missing model" boxes: use the block style. Licenses: THIRD_PARTY.md.

## Sky arena (demo stage)

`/function mcrobot_demo:arena` builds a floating stage far above the terrain: white concrete and quartz floor, glass rails, sea-lantern lights, start pad, finish gate, and the sections stairs (micro-steps),
slope, pit with bridge, narrow beam, turns, plus a spectator stand. `/robot demo arena` starts the scripted G1 on it (simulation, scripted velocity commands on the frozen walking policy), with a boss bar
timer and a scoreboard of runs; `/robot cam 1..4` teleports to camera spots. The layout is defined once in `server/mcrobot/arena.py` (used for the data pack, the MuJoCo export and the route);
the smoke test builds it in a real server, exports it with the real exporter and requires the MJCF to be identical. What it changes in the world: the arena blocks, forceloaded chunks around it, the
gamerules `advance_time` and `advance_weather` (set false, GLOBAL: fixed noon and clear weather; `arena/unlock` restores them), one scoreboard objective, one boss bar, and a once-a-second kill of every
non-player, non-ghost entity inside the arena box (mob spawning elsewhere is untouched). `arena/remove` undoes the build.

### Sky arena v2 (TV-style obstacle course)

`/function mcrobot_demo:arena_v2` builds a second stage 80 blocks north of the first (the first stays until the navigation work switches over). Eight sections, each with its own floor colour band and a floating label over a gate:
RAMP, BALANCE BEAM, SLALOM (pillars to weave around), DOORWAY (a gate wider than the G1 plus margin), ICE PATCH (packed ice: the exporter writes low friction, tested), LAVA BRIDGE, PUSH ZONE (pistons;
the pushes are real forces on the pelvis in MuJoCo and the in-game piston heads slide out in sync) and STAIRS, which are a ramp until M2 and say so on their label. START and FINISH gates, a checkpoint glow
(a floor strip, the next gate's lamps, particles and a sound) at the end of every section. `/robot demo arena_v2` runs the scripted G1 (simulation, scripted velocity commands on the frozen walking policy);
`/robot cam 5..8` are its camera spots. **No redstone anywhere**: heights come from carpet, snow layers and trapdoors, the piston heads are display entities moved by commands, and a test fails if any
arena v2 block or function contains "redstone", "repeater", "comparator" or "observer". The layout is defined once in `server/mcrobot/arena_v2.py`; `scripts/export_arena_v2.py` writes the MJCF, the header and
the route (checkpoints, pushes) for the demo and the navigation training; `scripts/verify_arena_v2.py` simulates the lap. Mod 0.0.6 adds the `cue` run event and the `arena_v2` demo argument. The 26.3 differences in
`block_display` syntax live in a data pack overlay (`overlay_26_3`).

## Run the tests (no Minecraft needed)

```
python3 -m venv .venv && .venv/bin/pip install numpy mujoco pytest pillow
make test-matrix           # every supported version: Python tests, mod build, Java tests, mod <-> Python server integration test
make test-matrix-smoke     # plus a real Fabric server boot per version (needs MCROBOT_EULA_FILE=<your accepted eula.txt>)
```

The matrix script takes versions as arguments (`scripts/test_matrix.sh 26.3`), waits while NUC load is 20 or more, and runs at nice 10 with 2 Gradle workers.
Java toolchain: Temurin JDKs 17, 21 and 25 unpacked in `~/opt` (no sudo; Gradle itself runs on 25), Gradle via the wrapper. `make build-all` writes `mod/dist/mcrobot-<mod>+<mc>.jar`.
`.github/workflows/ci.yml` runs the same matrix (not pushed; there is no remote).
